# 002 API

## Purpose
Define the external API contracts consumed by this plugin (Mapflow backend REST API).

## Content

Interface type: REST JSON over HTTPS (plugin is the client, Mapflow backend is the server).

Base URL: `https://whitemaps-{env}.mapflow.ai/rest` where `{env}` is one of: production (empty), staging, internal, duty.

#### The `mapflow.ru` domain

The Mapflow backend is not reachable from some networks through `mapflow.ai`. When the QGIS global variable
`mapflow_ru` is `true`, the plugin uses the domain `mapflow.ru` in place of `mapflow.ai`.

- The plugin reads the variable together with `mapflow_env`. The value is compared without case. Every other
  value, and no value, means `mapflow.ai`.
- The domain changes in every address that the plugin builds or opens: the API, the sign-in, Mapflow Web, and
  the links in the texts of the plugin.
- Only the domain changes. The host prefix, the realm, the client, the path and `mapflow_env` stay.
- `mapflow.ru` is a proxy of the same service. The sign-in configuration in the QGIS authentication database
  keeps its name, and the plugin writes the addresses of the domain in use into it.
- The server builds some addresses itself (image previews, result tiles, downloads), and they can have a
  `mapflow.ai` host. When the plugin uses such an address for a request, a layer source or a link, it changes
  the domain in the same way. It does not change an address that it sends back to the server, and it never
  changes the address of a user's own provider.
- The plugin has no control for this variable. Support gives it to a user who needs it.
- E-mail addresses and `metadata.txt` do not change.

### Authentication

Two mechanisms:
1. **Basic Auth (Token):** Header `Authorization: Basic {base64(token:)}`. Token stored in `QgsSettings("mapflow/token")`.
2. **OAuth2 (Keycloak):** Authorization Code with PKCE. Realm at `https://auth-{env}.mapflow.ai/auth/realms/mapflow-{env}/`. Tokens managed by QGIS Auth Manager.

Custom header on all requests: `x-plugin-version: {version}`.

### Error model

Multiple formats depending on source:
- Standard API: `{"code": string, "message": string, "params": object}`
- Data Catalog: `{"detail": {error_data}}`
- Fallback: raw response text

### Versioning policy
The plugin declares `x-plugin-version` on every request. The backend may respond with update notifications. Breaking API changes are reflected in major plugin version bumps.
